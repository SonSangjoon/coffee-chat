# Coffee Chat implementation Quality Map

`coffee-chat` owns the current product behavior, Taste vocabulary, lifecycle
contracts, and implementation verification. This map does not measure product
value or candidate-level output quality; those claims belong to
`coffee-chat-eval` and `coffee-chat-bench`.

## Product contracts and generated boundaries

| Field                 | Evidence                                                                                                                                             |
| --------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------- |
| Objective             | Keep engine, instance, Skill, schema, generated-artifact, and provenance boundaries explicit.                                                        |
| Acceptance criteria   | Valid source-of-truth inputs generate the declared projections; invalid ownership, role, path, schema, or provenance state is rejected.              |
| Failure modes         | Generated drift, cross-role leakage, private fixture leakage, invalid schema, stale provenance, and accidental writes outside the declared boundary. |
| Oracle                | Parsed schemas, generated file manifests/digests, ownership diagnostics, transaction receipts, and forbidden-path assertions.                        |
| Evidence tier         | `contract` and `behavior`                                                                                                                            |
| Representative suites | `foundation-contracts`, `role-contracts`, `task-4-projections`, `artifact-boundaries`, `fixture-isolation`, `workflow-contracts`.                    |
| Gate/cost             | Local/PR; fast to medium.                                                                                                                            |
| Owner                 | `coffee-chat`                                                                                                                                        |

Exact generated bytes are asserted only where the generated artifact is the
declared contract. Internal implementation order and unconstrained prose are
not part of this objective.

## Public Skill behavior

| Field                 | Evidence                                                                                                                                     |
| --------------------- | -------------------------------------------------------------------------------------------------------------------------------------------- |
| Objective             | Route a user request through the correct Skill and produce the declared observable result without unsafe or unrelated writes.                |
| Acceptance criteria   | Representative prompts lead to the correct route, preview boundary, artifact/state transition, receipt, and cleanup behavior.                |
| Failure modes         | Wrong route, premature mutation, missing preview, credential exposure, unrelated file writes, recursion, invalid handoff, or silent failure. |
| Oracle                | Public Skill route, structured artifacts, filesystem diff, receipt status, forbidden-write checks, and explicit failure state.               |
| Evidence tier         | `behavior` and `acceptance`                                                                                                                  |
| Representative suites | `skill-evaluations`, `skill-contracts`, `coffee-init`, `coffee-sync`, `coffee-harvest`, `coffee-update`.                                     |
| Gate/cost             | Local/PR deterministic acceptance; medium.                                                                                                   |
| Owner                 | `coffee-chat`                                                                                                                                |

Static Skill text checks are retained only for required frontmatter, structure,
or mandatory policy. They are not treated as proof that a model will follow
the Skill. Scenario-level filesystem and receipt evidence is the primary oracle.

## Native host lifecycle

| Field                 | Evidence                                                                                                                                                                          |
| --------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Objective             | Install, discover, remove, and reinstall co-installed engine and instance plugins without changing unrelated host state.                                                          |
| Acceptance criteria   | Each supported host command succeeds in an isolated host configuration; installed bytes match source; unrelated sentinel state survives; cleanup removes the temporary host root. |
| Failure modes         | Real host configuration mutation, namespace collision, wrong plugin bytes, incomplete removal, stale inventory, sentinel mutation, or cleanup leak.                               |
| Oracle                | Host command exit status, JSON inventory, tree digests, isolated config paths, sentinel digest, and cleanup assertion.                                                            |
| Evidence tier         | `integration`                                                                                                                                                                     |
| Representative suites | `tests/plugin-lifecycle.test.ts`.                                                                                                                                                 |
| Gate/cost             | Pre-release/nightly/manual `npm run test:host`; expensive and host-dependent.                                                                                                     |
| Owner                 | `coffee-chat`                                                                                                                                                                     |

The host suite is excluded from the deterministic `npm test` gate. An absent
host is reported as an explicit unsupported skip; an available host with a
failed lifecycle command is a failure.

## Documentation site and projections

| Field                 | Evidence                                                                                                                                                |
| --------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Objective             | Publish only the approved static engine site and preserve instance/package boundaries in projections.                                                   |
| Acceptance criteria   | Static routes build, local links/assets resolve, dimensions/digests remain valid, and no personal or synthetic instance content enters the engine site. |
| Failure modes         | Broken route, invalid asset, leaked fixture, wrong projection, or unexpected external write.                                                            |
| Oracle                | Static build output, parsed links, asset hashes, route inventory, and publication-boundary assertions.                                                  |
| Evidence tier         | `acceptance`                                                                                                                                            |
| Representative suites | `site-build`, `site-publication-boundary`, `readme-assets`, `test:site`.                                                                                |
| Gate/cost             | PR acceptance plus separate browser gate; medium.                                                                                                       |
| Owner                 | `coffee-chat`                                                                                                                                           |
